# Local Music Spike Benchmark Harness

Status: evidence harness only. This repository did not install ACE-Step weights, generate audio, or
record an M5 Max/M4 Pro performance number.

The harness implements the reduced PR-6 contract from RFC 0001 sections 11.2–11.5, 17/PR-6, and
19.2. It prepares a fail-closed, resumable measurement boundary before model installation.

## Public interfaces

| Interface | Path | Contract |
| --- | --- | --- |
| CLI | `tools/local-music-benchmark/cli.mjs` | Dry-run, execute, resume, and manifest validation |
| Canonical matrix | `tools/local-music-benchmark/config/lofiever-spike-matrix.v1.json` | Duration 150/180/184, batch 1/2/4, warmup 1, repetitions 3 |
| Dry-run config | `tools/local-music-benchmark/config/dry-run.example.json` | Deliberately contains no effective paths, weights, or toolchain pins |
| Execute-config recipe | `tools/local-music-benchmark/config/prepare-execute-config.mjs` | Resolves and hashes already-installed paths without loading a model |
| Manifest schema | `tools/local-music-benchmark/schemas/local-music-spike-manifest.v1.schema.json` | Evidence for one matrix cell |
| Adapter sidecar schema | `tools/local-music-benchmark/schemas/executor-result.v1.schema.json` | Persistent adapter result for exactly one attempt |
| Dry-run fixture | `tools/local-music-benchmark/fixtures/dry-run-manifest.v1.json` | Deterministic schema-valid evidence fixture |

Both committed schemas are generated from the runtime Zod contracts. Tests fail on drift. They are
explicitly labeled `structural-schema-only`: filesystem evidence is a separate public validation
mode, because JSON Schema cannot prove that a consumed sidecar or candidate still exists.

## Execution boundary

Execute mode has one allowlisted transport: `persistent-jsonl-v1`. The harness constructs the
argv itself:

```text
<verified-python-bundle-realpath>
-P
<verified-adapter-script-snapshot-realpath>
--protocol
lofiever-benchmark-jsonl-v1
```

There is no configurable command vector, shell, environment wrapper, or vendor command at the
harness boundary. Configured environment overrides are not accepted. The child receives only the
small fixed environment selected and hashed by the harness. The map is cloned before any await,
matched to its receipt, and used unchanged at spawn; dynamic-loader variables and external
`PYTHONPATH`/`PYTHONHOME` are rejected. The `-P` argv plus generated `PYTHONSAFEPATH=1`
prevents the adapter snapshot
directory from shadowing the standard library, while `PYTHONNOUSERSITE=1` disables user-site
injection. The retained safety flags and virtual-environment paths are generated by the harness;
the bundled virtual environment resolves only its pinned snapshot packages.

The pinned adapter is part of the trusted computing base. The harness can prove which reviewed
Python executable and adapter bytes it started; it cannot prove that reviewed adapter code never
calls a subprocess or requests privilege internally. Consequently, the direct argv has no `sudo`,
but a no-`sudo` claim for the real smoke requires review of the exact pinned adapter digest. That
review receipt is mandatory before any real result is accepted operationally.

One adapter process is initialized per matrix cell and remains alive for its warmup and all
repetitions. Its initialization handshake must report the effective engine, model, LM model,
runtime, toolchain, and adapter identity. This is a consistency receipt from the pinned adapter,
not independent attestation that a model was loaded. A mismatch terminates the process before
generation evidence can become completed.

The initialization request also supplies a dedicated parent-liveness descriptor (`fd 3`) and the
harness PID. The reviewed adapter must arm a blocking watchdog on that descriptor and acknowledge
the exact pair before initialization succeeds. Kernel EOF therefore terminates the adapter even
when the harness itself receives `SIGKILL`; an abandoned process cannot keep a Metal workload
alive after its machine-wide lock disappears. This watchdog is part of the adapter review/TCB,
not a property the harness can infer from an arbitrary script.

The harness also inherits two kernel capabilities into the adapter before Python can inspect
behavior, models, or output: `fd 4` is the already pinned output root and `fd 5` is the already
pinned engine/adapter working directory. The adapter's first action is to `fstat` both, `fchdir`
through `fd 5`, and echo their exact device/inode/UID/mode receipts in initialization. Output paths
in the protocol are allowlisted relative components only. The reviewed adapter creates, opens,
publishes, and renames `cells/`, attempt, sidecar, and artifact files relative to retained
descriptors with `O_NOFOLLOW`; it never receives an absolute evidence destination.

The adapter process is terminated as a process group: `SIGTERM`, then `SIGKILL` after the
configured grace interval. stdout and stderr are streamed into bounded per-request buffers. A
timeout, output limit, process exit, invalid response, or spawn error becomes a structured failed
attempt.

## Pins verified before execute

The current config is the source of truth on every invocation. Execute aborts unless all of these
facts are present and verified:

- harness repository realpath, its exact current HEAD, and a clean tracked/untracked worktree;
- ACE-Step repository realpath, exact RFC commit
  `14c0211d5a0653b0f63e27686f4c3f151b4d8629`, and a clean tracked/untracked worktree;
- main model ID, full immutable 40-hex revision, weights realpath, and deterministic
  file/directory SHA-256;
- LM model ID, full immutable 40-hex revision, weights realpath, and deterministic
  file/directory SHA-256;
- adapter Python executable and script realpaths plus SHA-256, together with the source and
  private execution-snapshot digests for the Python runtime library tree and any detected virtual
  environment configuration/site-packages tree and its startup Mach-O closure;
- Git, the running Node executable, Python, `uv`, `ffmpeg`, and `ffprobe` realpaths, SHA-256
  values, and exact version output; the pinned Git executable performs both repository checks,
  the Node pin must be the process actually running the harness, and Python must be `>=3.11,<3.13`
  from a relocatable standalone `uv` runtime;
- device, LM backend, VAE chunk, harness commit, optional server commit, and hashed relevant
  environment receipt;
- the locally observed host identity: trimmed/bounded hostname, CPU model, positive physical
  memory, and OS identity. On macOS the OS value comes from absolute `/usr/bin/sw_vers`
  product/build probes with C locale, no shell, and bounded time/output; the harness does not use
  `sysctl` or trust host labels supplied by the config or adapter;
- a configured, canonical, current-user-owned `runtime.runDirectory` and parent with no
  group/world permissions. The manifest persists both identities as realpath/device/inode.

Directory pins reject symlinks and hash a sorted tree of entry names, types, and file digests.
Executable/script/model changes after config creation fail preflight. Every pin, both Git
worktrees, and the runtime Node identity are revalidated after acquiring the machine lock, before
each cell, and immediately before its one adapter spawn. The adapter initialization receipt must
match that observed host identity as well as the engine/model/runtime pins. After shutdown proves
the process group absent, the harness reopens the complete trusted source and effective snapshot
identity without creating or repairing anything. It validates artifact/sidecar evidence first,
then performs that read-only provenance check as the final boundary immediately before every
terminal checkpoint or terminal return.

Execute config and execute evidence are restricted to the RFC spike contract: engine commit
`14c0211d5a0653b0f63e27686f4c3f151b4d8629`, durations `150/180/184`, batches `1/2/4`, MPS,
MLX, one warmup, at least three repetitions, and a non-null positive integer VAE chunk. Dry-run
may keep unavailable hardware/model fields nullable.

The adapter working directory must be the verified engine repository. The harness reads the
adapter script and `ffprobe` from their verified descriptors into deterministic, read-only
execution snapshots directly under the pinned run directory. Python is snapshotted as a private
bundle that preserves `bin/../lib`; internal runtime symlinks are confined and rewritten inside
that bundle. When the configured Python path belongs to a virtual environment, the harness also
snapshots its `pyvenv.cfg` identity and site-packages, generates and hashes a bundle-local effective
`pyvenv.cfg`, and points the child only at those snapshot paths. Command receipts and the effective
manifest identify the executable, source trees, snapshot trees, and hashed environment. The
adapter and duration probe therefore execute the bytes that passed verification, not a mutable
source path checked earlier.

On macOS, the harness recursively parses `LC_LOAD_*` and `LC_RPATH` with `/usr/bin/otool`. Each
non-system image records lexical path, realpath, SHA-256, device, inode, rpaths, and dependency
edges plus the selected Mach-O slice. The root slice (`arm64`, with controlled `arm64e` fallback,
or the recorded x86 equivalent) is propagated to every pinned image; mixed slices fail closed.
Every distinct inherited-rpath context is inspected, and a repeated image whose dependency graph
would resolve differently is rejected. `LC_DYLD_ENVIRONMENT` is forbidden because it can redirect
loads outside the recorded graph. Every recognized load/rpath command must contain exactly one
complete, control-character-free name/path field; malformed `otool` output fails closed. Only
literal `/usr/lib/` (including `/usr/lib/dyld`) and
`/System/Library/` loads are treated
as system TCB, tied to the recorded macOS build and architecture. Runtime validation recomputes
the closure digest and proves that the root, every reachable pinned dependency, and the exact
system-edge set refer to the recorded graph; orphan images and extra system loads are rejected.
Execute manifests require non-null adapter, `uv`, and `ffprobe` closure receipts with coherent
platform identities. The private Python bundle must contain every non-system
startup image. Standalone uv CPython 3.11/3.12 satisfies that boundary; Homebrew framework Python
is rejected with `python_framework_launcher_not_supported` because its absolute framework and
Python.app launcher escape the relocatable bundle. The `ffprobe` snapshot may depend on pinned
Homebrew dylibs, so its complete closure is persisted and recomputed immediately before every
artifact probe spawn.

This is a static Mach-O startup-closure receipt, not a claim to the adapter's complete native TCB.
It does not discover arbitrary later `dlopen` or `execve` calls. The reviewed persistent adapter
and its installed packages remain part of the smoke review boundary.

Python `.pth` files are part of that trust boundary. A line may contain only a simple
`import module_name` whose complete module resolves inside the snapshotted site-packages tree
(including uv's `import _virtualenv`). The pinned interpreter probes with `-I -S`, an environment
without `PYTHONPATH`, and the builtin/frozen/path finders against the explicit snapshot directory;
it never imports the candidate module or a shadowable `json.py`. A builtin/frozen module such as
`os` is rejected even if same-named `os.py` and hostile helper modules are placed beside the
`.pth`. Arbitrary import code, missing/external modules,
absolute paths, relative escapes, invalid encodings, and editable installs are rejected.

Dry-run records the current harness commit for deterministic identity but performs no engine,
model, adapter, toolchain, version, or weight-path checks. Harness repository path/cleanliness and
all other unavailable effective fields remain `null` with `dry_run` reasons; null is never
converted to zero.

## Dry-run before weights

Run from the repository root:

```bash
install -d -m 700 "$HOME/lofigen/staging"
BENCHMARK_OUT="$(mktemp -d "$HOME/lofigen/staging/dry-run.XXXXXX")"
BENCHMARK_OUT="$(cd "$BENCHMARK_OUT" && pwd -P)"
node tools/local-music-benchmark/cli.mjs \
  --config tools/local-music-benchmark/config/dry-run.example.json \
  --output "$BENCHMARK_OUT" \
  --dry-run
```

Expected files:

```text
benchmark-index.v1.json
manifests/d150-b1.json
manifests/d180-b1.json
manifests/d184-b1.json
manifests/d150-b2.json
manifests/d180-b2.json
manifests/d184-b2.json
manifests/d150-b4.json
manifests/d180-b4.json
manifests/d184-b4.json
```

The output root must already exist, be current-user private, and be supplied by its exact physical
path: any intermediate/final symlink or missing root is rejected before the confined helper or
adapter starts. The helper source is captured through a stable descriptor and must match the
reviewed SHA-256 literal in the already loaded parent module before `node --eval` can start it.
It pins root/manifests/cells directory identities for its lifetime and never respawns or falls back.
Every first dry-run receipt is written to an exclusive temporary file, reread and `fsync`ed, then
published with an exclusive hard link followed by directory `fsync`; it is never exposed through a
partially written final name. Executable checkpoint CAS updates instead use a verified temporary
file plus relative atomic rename only after the expected prior receipt matches. Repeating the same
dry-run accepts only byte-identical files; it never replaces execute evidence or a different
dry-run receipt.

Validate only the JSON structure through the public CLI:

```bash
node tools/local-music-benchmark/cli.mjs \
  --validate-manifest "$BENCHMARK_OUT/manifests/d180-b1.json"
```

This command deliberately does not claim that terminal artifacts exist. `--validate-evidence`
accepts only an execute manifest in `completed` or `completed_with_errors`; dry-run, `planned`,
`running`, and `interrupted` manifests fail before evidence is accepted. For a terminal execute
manifest, a missing sidecar, candidate, or changed duration also fails with a non-zero exit:

```bash
node tools/local-music-benchmark/cli.mjs \
  --validate-evidence "$BENCHMARK_OUT/manifests/d180-b1.json" \
  --config "$HOME/lofigen/spike-001.config.json" \
  --output "$BENCHMARK_OUT"
```

`--config` is mandatory here and must be the original, locally prepared, trusted execute config;
never copy it from or derive it from the evidence bundle being checked. Evidence validation first
pins the output root and manifest file (including directory/file identity and manifest SHA-256),
then statically rejects non-terminal/schema-invalid data before loading trusted tools. It derives
the expected cell from that config plus the canonical matrix, performs a read-only provenance
check, validates files using only the correlated effective `ffprobe`, and repeats provenance as
the final check. Missing snapshots are rejected; this mode never creates, repairs, renames, or
copies TCB files. `--validate-manifest` remains structural-only and executes no configured tool.

## Preparing an executable config

The executable recipe consumes only already-installed local paths. It does not download weights,
load a model, or start the adapter. Create a private parent/run directory, then provide immutable
model revisions, the reviewed adapter path, and the tool executables:

```bash
install -d -m 700 "$HOME/lofigen" "$HOME/lofigen/run"

LOFIEVER_BENCHMARK_ID=lofiever-spike-001 \
LOFIEVER_ENGINE_REPOSITORY=/absolute/path/to/ACE-Step-1.5 \
LOFIEVER_MODEL_ID=<exact-model-id> \
LOFIEVER_MODEL_REVISION=<40-hex-model-revision> \
LOFIEVER_MODEL_WEIGHTS=/absolute/path/to/model-weights \
LOFIEVER_LM_ID=<exact-lm-id> \
LOFIEVER_LM_REVISION=<40-hex-lm-revision> \
LOFIEVER_LM_WEIGHTS=/absolute/path/to/lm-weights \
LOFIEVER_VAE_CHUNK=8 \
LOFIEVER_RUN_DIRECTORY="$HOME/lofigen/run" \
LOFIEVER_ADAPTER_SCRIPT=/absolute/path/to/reviewed-persistent-adapter.py \
LOFIEVER_GIT=/usr/bin/git \
LOFIEVER_PYTHON=/absolute/path/to/uv-managed/cpython-3.12/bin/python3.12 \
LOFIEVER_UV="$HOME/.local/bin/uv" \
LOFIEVER_FFMPEG=/opt/homebrew/bin/ffmpeg \
LOFIEVER_FFPROBE=/opt/homebrew/bin/ffprobe \
node tools/local-music-benchmark/config/prepare-execute-config.mjs \
  --output "$HOME/lofigen/spike-001.config.json"
```

`LOFIEVER_PYTHON` must be an explicit absolute path to standalone uv CPython 3.11 or 3.12. The
recipe validates its version and relocatable startup closure before publishing any config;
`command -v python3`, a floating alias, system Python, and Homebrew framework Python are not valid
inputs. On macOS, Python, `uv`, and `ffprobe` must themselves be native Mach-O executables with
recorded closures; a pinned shell wrapper cannot delegate to unrecorded bytes. Pinned native uv
ownership and its closure are revalidated again at the execution boundary. Optional
numeric/environment values use strict decimal/enum/commit parsing:
malformed values fail without leaving a partial output config.

The Python version passed to pinned `uv python find` includes the complete `X.Y.Z` patch, so an
installed uv-managed 3.12.9 is not silently replaced by a preferred 3.12.11. Tool probes receive
only `HOME`, `TMPDIR`, `LANG`, and `LC_ALL`; `DYLD_*`, `LD_LIBRARY_PATH`, and `LD_PRELOAD` are
rejected before any recipe subprocess. This matrix accepts exactly `device=mps` and
`lmBackend=mlx`; `LOFIEVER_VAE_CHUNK` is required and must be a positive integer selected for the
real smoke setup (the example value is not an inferred benchmark result).

The resulting configuration uses the committed canonical matrix and contains measured pins for:

- `engine.repositoryPath`;
- `model.weights` and `model.lm.weights`, each with `path`, `realpath`, and `sha256`;
- immutable `model.revision` and `model.lm.revision`;
- private `runtime.runDirectory` (normally `$HOME/lofigen/run`) shared by every harness output on
  the machine;
- `adapter.workingDirectory`, `adapter.executable`, and `adapter.script`;
- `toolchain.git`, `toolchain.node`, `toolchain.python`, `toolchain.uv`, `toolchain.ffmpeg`, and
  `toolchain.ffprobe`, each adding `version`; the effective execute manifest (not the portable
  input config) also carries the verified `uv` and snapshotted `ffprobe` closure receipts;
- the observed host/runtime fields.

Do not version machine paths, weights, caches, generated audio, or secrets.

Create each execute output privately before running:

```bash
install -d -m 700 "$HOME/lofigen/staging/spike-001"
BENCHMARK_OUT="$(cd "$HOME/lofigen/staging/spike-001" && pwd -P)"
```

Execute one conservative cell first:

```bash
node tools/local-music-benchmark/cli.mjs \
  --config "$HOME/lofigen/spike-001.config.json" \
  --output "$BENCHMARK_OUT" \
  --execute \
  --cell 150:1
```

Without `--cell`, cells run in batch-escalation order: all B1, then B2, then B4. A new output may
start only with `150:1`. `--cell` reopens and validates every preceding manifest against the
current config; B2 cannot start until every B1 receipt is green, and B4 cannot start until every
B1/B2 receipt is green. Merely declaring `state: completed` is insufficient. An allocation
failure in warmup or a repetition ends that cell, marks its remaining repetitions `skipped`, and
prevents every later equal-or-larger batch from spawning.

The final CLI receipt includes a count by terminal `states`. Any execute receipt containing a state
other than `completed` has `ok: false` and the process exits non-zero. A full sweep stops after its
first non-completed cell and emits that accumulated receipt; it does not replace the originating
failure with a later predecessor-sequence error.
If a completed adapter result reports an effective batch below the requested B2/B4 factor, the
manifest retains that measured fact but the CLI receipt includes
`batch_effective_below_requested`, sets `ok: false`, stops the sweep, and exits non-zero.

## Persistent sidecar protocol

Each attempt gets a new exclusive directory:

```text
cells/d<duration>-b<requested>/<phase>-<index>/attempt-<attempt>/
```

The reviewed adapter protocol requires one atomic `executor-result.json`, followed by an
acknowledgement for the same `requestSha256` over JSONL. Every request carries a monotonic
`protocolRequestId`. After the first response, the harness sends `confirm-response-boundary`; only
the matching `response-boundary` can resolve the request. Any additional response emitted before
that confirmed boundary poisons the session, including a second line delayed into a later stream
chunk. Any byte after the boundary is also fatal, including a partial JSONL frame between requests;
the final manifest is not checkpointed as terminal until the shutdown boundary and process close
leave the session healthy. Shutdown must resolve to the exact acknowledgement
`{"type":"shutdown-complete"}` after the correlated boundary; a different type or any extra field
is a protocol failure. After close, the harness reopens and revalidates every candidate and
consumed sidecar before it writes either terminal state. The sidecar identity contains:

- run and configuration hashes;
- duration and requested batch;
- phase, record index, and attempt;
- command and request hashes.

The harness opens the sidecar with `O_NOFOLLOW`, validates its schema and full identity, and
renames it to `executor-result.consumed.json`. Invalid sidecars are quarantined. Missing,
incomplete, mismatched, or `status: failure` sidecars can never produce a completed record.
Checkpoint acceptance reparses that consumed sidecar and crosses its request identity, declared
candidates, nullable metrics, unavailable reasons, and structured error against the record.
Each nullable sidecar metric has exactly one of a value or an unavailable reason. Allocation and
interruption flags must agree with the structured error category; contradictions fail before a
terminal checkpoint is accepted.

A successful B2/B4 sidecar has one entry per effective candidate:

```json
{
  "schemaVersion": "1.0.0",
  "identity": {
    "runId": "<64 lowercase hex>",
    "configurationSha256": "sha256:<64 lowercase hex>",
    "durationSeconds": 180,
    "batchSizeRequested": 2,
    "phase": "repetition",
    "index": 1,
    "attempt": 1,
    "commandSha256": "sha256:<64 lowercase hex>",
    "requestSha256": "sha256:<64 lowercase hex>"
  },
  "status": "success",
  "metrics": {
    "peakMemoryBytes": null,
    "energyWh": null
  },
  "metricUnavailableReason": {
    "peakMemoryBytes": "not_collected",
    "energyWh": "not_requested"
  },
  "candidates": [
    {
      "index": 1,
      "durationSeconds": 179.8,
      "wallTimeSeconds": 90.0,
      "outputFile": "cells/d180-b2/repetition-1/attempt-1/artifacts/candidate-1.wav"
    },
    {
      "index": 2,
      "durationSeconds": 180.1,
      "wallTimeSeconds": 91.0,
      "outputFile": "cells/d180-b2/repetition-1/attempt-1/artifacts/candidate-2.wav"
    }
  ],
  "error": null
}
```

`batchSizeEffective` is derived from contiguous candidate indices `1..N` and must be between one
and requested batch. The adapter-declared duration is retained separately for audit, but the
record duration comes from pinned `ffprobe`. Candidate and batch wall times are retained
individually. The record audio duration is the sum of measured candidate durations, and RTF is:

```text
rtf = measuredBatchWallTimeSeconds / sum(actualCandidateDurationSeconds)
```

The harness never trusts a declared duration or executor-provided artifact hash. Every artifact
must live below the current attempt's `artifacts/` directory. Indices, inode identities, and
digests must all be unique. A single reviewed confined helper retains the complete directory chain,
reads the regular file twice without creating missing directories, and returns one exact Buffer
plus full file receipt. Artifact Buffers are capped separately at 64 MiB so the RFC 184-second,
48 kHz, 24-bit stereo WAV (~53 MiB) remains representable; the JSONL/base64 helper frame is bounded
at 96 MiB, while manifest/checkpoint text, adapter stdout/stderr, and sidecars remain capped at
16 MiB. The harness hashes that
exact Buffer and writes all of it to pinned `ffprobe` on `pipe:0`. `ffprobe` must drain stdin and
report one audio stream plus bounded frame `nb_samples`; duration is `sum(nb_samples)/sample_rate`.
After the probe, the helper rereads the public artifact and requires identical receipt, digest, and
bytes before a checkpoint can advance. It records device, inode, bytes, SHA-256, and that measured
duration; a directory swap, same-inode rewrite, short-reading probe, or post-probe change fails.
This is deliberately a retained-chain, exact-Buffer handoff with a final public-file reread; it is
not a same-file-descriptor claim across the Node harness and the separate `ffprobe` process.
Each measured candidate and its adapter-declared duration must each be within the explicit
conservative `±1.0s` boundary of the cell's requested duration, and the declaration must also be
within `±1.0s` of the same `ffprobe` measurement. Thus requested/measured/declared
`180/181/182` is rejected even though each adjacent pair is one second apart. This accommodates
container/sample rounding while rejecting truncated or substituted audio (for example, a
0.25-second WAV cannot satisfy a 180-second cell).
If a post-start failure has no positive monotonic measurement, `wallTimeSeconds` remains `null`
with `monotonic_measurement_unavailable`; the harness never substitutes epsilon or zero.

## Checkpoint, lock, and resume

Before any adapter spawn, the CLI acquires one UID-scoped machine-wide lock at the stable OS path
`/tmp/lofiever-local-music-metal-<uid>.lock` and holds it across all selected cells, configured run
directories, and output directories. Its location is independent of the mutable configured run
directory tree, so renaming/recreating either `runDirectory` or its private parent cannot create a
second lock island. The lock itself must be owned by the current UID and have no group/world
permissions. One per-output session lock is shared by dry-run and execute and is held across the
entire selected matrix sweep, including the interval between cells. A concurrent mode is rejected;
dry-run cannot overwrite an execute checkpoint during or after a sweep. Machine-lock owners contain
the parent PID/start identity, hostname, timestamp, process identity, and a unique acquisition
identity. Per-output owner schema 1.1 additionally pins the confined helper PID and its exact start
identity. Another hostname or any unverifiable live start identity is a conflict, never stale. A
per-output owner is stale only after both the exact parent and exact helper are absent or their PIDs
have been proven reused. Recovery is serialized by an exclusive owner guard and passes the originally
observed full file receipt into the quarantine rename, so a second contender cannot rename a live
replacement; malformed locks fail closed.
The macOS process-start query uses absolute `/bin/ps` with `LC_ALL=C`, `LANG=C`, `TZ=UTC`, no
shell, and no inherited environment, so lock identity cannot drift with the contender's locale or
timezone. Hostname is observed once per owner/stale decision and reused for the start hash and all
owner fields; an observation change is an identity conflict, never evidence of staleness.

On POSIX, the adapter is isolated in a detached process group. Shutdown targets the recorded PGID,
not merely the leader PID, and verifies group disappearance after TERM/KILL. The first observed
`ESRCH` ends that cleanup attempt; a later process-group reuse is never signalled.

Both the per-output lock and the UID-scoped machine lock durably publish a private
`*.cleanup-unproven` guard in `cleanup-pending` state **before each cell can spawn**. The machine
guard is cleared after a cell's adapter close proves absence and is re-armed with a `null` PGID for
the next cell, so no new process can inherit a previous cell's proof. Immediately after `spawn`,
but before the initialize/model boundary, the executor durably records the new positive PGID in
both guards. Failure to arm aborts before spawn; failure to record the PGID terminates the new group
and leaves the earlier pending guard in place. A normal proven close removes both pending guards.
Unproven cleanup changes them to `cleanup-unproven`; if that update itself fails (for example,
ENOSPC), the already durable pending guard remains fail-closed across process exit.

Normal per-output release is coupled to confined-helper shutdown and has no standalone `release()`
API. After the guard is proven absent, the helper verifies the exact lock receipt, enters a terminal
state that rejects queued or later requests, then CAS-unlinks the lock and `fsync`s its directory as
its final filesystem mutation. It only acknowledges after that boundary, closes retained handles,
and must exit zero; the CLI emits success only after the exact acknowledgement and exit. A crash
before unlink retains the lock. A crash after unlink cannot return to filesystem work and still
causes the caller to fail. `cleanup-unproven` never takes this terminal release path.

The guard stores lock owner, state, positive PGID or `null`, nullable structured error code, and a
canonical digest rederived from state/error/PGID fields; it never stores raw error text. Acquisition
revalidates owner, file receipt, and that digest under the stale-recovery guard. A stale
`cleanup-pending` guard is auto-quarantined only when it contains a positive PGID and one native
`kill(-processGroupId, 0)` probe returns `ESRCH`. `cleanup-unproven`, `null` PGID, `EPERM`, a live
group, malformed data, or any identity/digest change always blocks automatic recovery.

Manual recovery remains fail-closed for those blocked states. Do not delete the guard or retained
lock merely because the parent PID exited: the exact per-output helper PID/start identity must also
be absent or proven reused. An operator must read `processGroupId`, use an audited native probe to
establish `ESRCH`, and independently confirm that no benchmark/Metal workload or confined helper
remains. If the guard records `null`, recovery needs an equivalent positive host-level proof, such
as a reboot followed by workload inspection. Only after those proofs may the operator archive or
remove both the guard and its retained lock. The harness has no automatic override for this gate.

Execute outputs and the run directory must be current-user-owned and private. The harness pins
their directory identity and verifies it around use; a parent rename/replacement fails closed
instead of redirecting evidence.

Every transition is durably checkpointed. Resume:

1. rebuilds the plan from the currently validated config and current harness commit;
2. rederives configuration, run, command, request, chained attempt, summary, and state invariants;
3. reopens and rehashes all completed candidates, remeasures them through pinned `ffprobe`, and
   reparses every consumed sidecar receipt;
4. rejects any change before adapter spawn;
5. skips completed, failed, and skipped evidence;
6. retries only `interrupted` records whose structured error is explicitly `retryable: true`.

`--validate-evidence` holds one pinned output-root/helper capability throughout the check. It
requires the same full manifest file receipt, digest, and bytes on every read, rejects intermediate
symlinks and root/file replacement, and rejects dry-run, planned, running, or interrupted state
before loading the trusted config or spawning an artifact probe. Only a terminal execute manifest
whose complete configuration matches the trusted config/matrix proceeds to filesystem evidence.

A stale `running` record from a dead process becomes non-retryable `execution_abandoned`, and all
later planned records become `skipped_after_abandoned_attempt` in the same durable checkpoint;
ordinary exceptions become checkpointed `executor_unhandled_failure`. Neither is silently
replayed. SIGINT/SIGTERM becomes a structured retryable interruption and receives a new attempt
directory on resume. Every terminal attempt carries a digest over request, command, sidecar,
candidates, metrics, and error plus the previous attempt digest, forming a retry chain.
The manifest retains the full terminal payload for every attempt in an append-only
`attemptReceipts[]` sequence. Attempts must be contiguous from one, every link is rederived, and the
last stored receipt must equal the current record evidence; an arbitrary previous hash is invalid.
Every historical predecessor is restricted to a retryable `interrupted` result with no sidecar or
candidates. Therefore every sidecar referenced anywhere in an accepted chain is the current
terminal sidecar and is reopened by evidence validation; completed or failed evidence cannot be
hidden in an unvalidated historical attempt.

## Summary consistency

The runtime schema recalculates and validates:

- unique contiguous repetition indices and exact state/status combinations;
- completed/failed/skipped/pending counts;
- allocation-failure count, including warmup;
- RTF mean and population standard deviation from completed repetitions only;
- effective batch agreement across completed repetitions;
- finalized energy total only when every completed repetition reports energy.

Unavailable aggregate energy is `null` with a reason, never zero. A terminal manifest can never
retain `not_reported_yet`: it resolves to `not_requested`, `no_completed_repetitions`, or
`not_available_for_all_completed_repetitions`. This mutable audit reason is deliberately outside
the immutable configuration/run hash and is instead schema-checked against the derived summary.

## `profile_inference.py` is auxiliary only

`profile-inference.mjs` exposes one explicitly named one-shot auxiliary command builder for
manual comparison against the pinned vendor script. It is not a configured executor, does not
participate in warmup/repetition lifecycle, and cannot produce decisive completed evidence.
There is no exported vendor benchmark command.

The decisive smoke performed after weights are installed must use a separately verified
persistent adapter implementing the protocol above. This PR tests that protocol with
`fixtures/fake-persistent-adapter.py`; the fixture never loads a model and writes only
low-sample-rate, requested-duration WAV fixtures for `ffprobe`-boundary tests. A real adapter's
exact digest and code-review receipt are still mandatory for the later smoke.

## Verification

This harness intentionally uses native ESM JavaScript rather than the application TypeScript
pipeline: it is a zero-build operational evidence tool that must run before the Next.js/server
build exists. The exception is limited to `tools/local-music-benchmark/**`. Node syntax checking is
the lint-equivalent gate, followed by the behavioral suite:

```bash
find tools/local-music-benchmark -type f -name '*.mjs' -print0 | xargs -0 -n1 node --check
node --test tools/local-music-benchmark/*.test.mjs
```

CI runs that full contract in a blocking Node 20 job, including schema/fixture drift and the CLI
vertical tests.

dry-run, schema and fixture drift, process persistence, sidecar fail-closed behavior, bounded
streams, extra-response rejection, TERM/KILL timeout, machine-wide lock/stale recovery, private
root replacement, retained-chain Buffer hashing/`ffprobe pipe:0`, attempt confinement and inode/digest
uniqueness, candidate/RTF consistency, post-start failure receipts, allocation stops, chained
checkpoint tampering, abandoned-running recovery, finalized energy reasons, SIGINT, CLI resume,
public B1/B2/B4 cell gates, locally observed host/adapter-handshake mismatch, trusted-config
evidence validation, no-repair post-close provenance, pinned-root/manifest rewrite and symlink

inherited-rpath ambiguity rejection, and recursive Python/uv/ffprobe Mach-O closure revalidation.

## Future lofigen-server integration

This PR does not modify or depend on lofigen-server routes. A future server-backed persistent

by this harness.
